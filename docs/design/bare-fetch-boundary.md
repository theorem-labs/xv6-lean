# General Bare fetch boundary

BareJalFetch already provides a generic actual outer fetch Plan and native
chunk fold. Its previous public wrapper only exposed F_Base results.
BareFetch reuses those proofs and generalizes the byte-backed public result
to F_Base/F_RVC, retaining the same nine-cell footprint and Config.

The actual KptFetch.instrBytes predicate supplies alignment, classification
and each required identity-tier RX/pristine discarded window. It is false
for error-result constructors. select_word produces the concrete selected
word and actual parts, then the existing generic fold executes the real
Bare translation/PMA/PMP/memory events. parts_addresses rewrites the guard
to KptFetch.chunks pc result, with one later and quantified view per read.

For aligned PC a compressed instruction still reads all four bytes. For
PC mod4=2 it reads one halfword; a base instruction reads two ordered
halves and preserves the original fetch start. The complete owned code,
register cells, running context and read receipts return. The final native
Link supplies every chunk/Plan implementation internally; only the genuine
continuation is supplied by the caller. This rule alone does not decode,
execute, retire or prove the source entry resources reachable.
