# Native mycpu active-step entry on the common footprint

Implemented and frozen: `Xv6/Kernel/MycpuCycleEntry{Defs,Spec,Plan,Proofs,Link}.lean` and status only. The existing CycleBody and Active modules remain frozen. The result is four native CPS rules for actual `run_hart_active stepNo`, covering the nine scalar, two store, two load and final return indices. The coordinator separately owns setup, retirement, clock/restart and function composition.

The register resource is exactly `MycpuCycleBody.cells` with its same 28 unique keys and shares. Entry configuration is `MycpuActive.Config rs index fetchRegion`, including actual supervisor interrupt conditions, Bare translation, TOR PMP grant, PMA/HTIF facts, PC/width, checked decoder configuration and elp=0. Memory/return body configuration is additionally stated at the original register file, and is transported through the nextPC-only preparation by pure projection equalities. There is no new supervisor-entry, KPT, pointer-identity or translation assumption disguised as a callback.

Each implemented public family rule consumes the generation certificate, the common cells, running context, the actual persistent discarded 34-byte physical span, and the current reservation fragment. The span is the already allocated `MycpuFetch.shared`; extraction of an indexed discarded context window reuses MycpuBootResources and never duplicates fractional timestamps. Memory rules also consume an actual eight-byte context word at SP+offset: full old ownership for a store, arbitrary fraction for a load. Alignment follows from that resource. The fetch window may overlap other fetch windows because the span is discarded; the data resource is kept separate and linear.

The conclusion executes `run_hart_active stepNo >>= continuation`. Its successful continuation receives `Step_Execute (Retire_Success (), MycpuActive.instbits index)`. Returned register files are exactly `MycpuScalar.after scalar (prepared index rs)`, `prepared index rs` for a store, `MycpuMemory.after slot (prepared index rs) word` for a load, and `MycpuReturn.after (prepared 13 rs)` for return. The full context/span remain; loads and register-only bodies retain the original reservation, while stores return none. Stores return the actual original data-register value and loads retain their original word/fraction. Scalar/return rules expose the fetch view receipt; memory rules expose both fetch and data-event receipts. No order between receipts is invented.

The continuation is guarded once for scalar/return, twice for a memory body: the concrete fetch event and subsequent concrete data event pay those two guards. This counts only known native memory boundaries and does not depend on how many register prefix events happen. The final contracts contain ordinary terminal-continuation WPs and no assumption proving the instruction body or preserving a machine state.

Proof factorization is structural. Widen the actual dispatch RegisterPlan, the full MycpuFetch fixed-word boundary, and Active preparation Prefix to the same 28-cell bundle. Use the unconditional `run_hart_active` factorization, the exact no-pending interrupt plan (three universal external/pending reads retained), and the native context-backed fetch fold. Its original residual keeps all response/error and possible second-fetch paths; only the actual owned word selects the checked result. Fold preparation to the actual execute tail, then apply the proved CycleBody family rule and exact Step wrapper equality. An internal generic CPS entry lemma can expose a residual WP as a composition rule, but every final family theorem discharges it with these implementations.

Source boundaries remain generated `Step.lean:321–396`, `Fetch.lean:232–284`, and pinned `SmodeCore.v:167–248` / `CodeMycpu.v`. True instruction widths are two/four even when the fetch footprint reads four. The compressed Zca test, landing-pad read and the single ExecuteAs redirection remain actual generated operations. Full sconf/SIE capability, KPT path, retirement, function chaining, ABI result and paper adequacy are not claimed.
