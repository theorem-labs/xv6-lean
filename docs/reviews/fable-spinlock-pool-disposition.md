# Disposition of the concrete annotation review

The fifth Fable review approves with changes. Its main correction is accepted:
protocol relations quantify over valid resource successors, but an operational
annotation must fix its timestamps and counter values from the actual event.
The concrete pool agent is revising its transition to force that update and
prove functionality. This remains an open obligation; a conditional exclusion
lemma from a pure owner witness alone does not close the application theorem.

A physical-PC corollary will be stated at instruction boundaries only. A
mid-instruction PC theorem needs an additional commit invariant; the current
terminal Family certificate does not supply one. The event-defined holder
window remains the principal exclusion property. The concrete `Holds`
definition already checks power and generation liveness.

The swap-write kind must explicitly imply the exclusive view update. The
agent will check that fact in the actual exclusive/conditional pair. Actual
code reads use `CodeUnwritten.read_code` and advance views; the proposal's
old timestamp-zero wording is removed. Device frame, fence identity,
reservation conflict, power precondition and arbitrary boot-witness lemmas
remain explicit coverage obligations. The native all-schedule safety theorem
already composes the actual boot handler, but does not prove these annotation
obligations by itself.

The bounded transport checkpoint remains the next review gate: exact register,
pin and restart cases, and both outcomes of one exclusive/conditional pair.
Counter/store/unlock, other-hart framing, all workers/power and full `Covers`
follow after independent checking. The positive interference witness can
continue independently because it proves actual `NodeSteps`/`PoolSteps`
without assuming the annotation. Its annotation will be connected only after
the unique update and coverage proof exist; Fable's suggested serialization
of these independent proof tasks is not required for soundness.

This disposition records accepted work and limits, not completion of the
operational exclusion or full two-hart integration gate.
